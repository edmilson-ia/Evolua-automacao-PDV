# Evolua Automação — Sistema PDV/ERP White-Label (PWA)

Skill de contexto para o projeto "Evolua Automação": sistema de PDV + ERP simplificado, white-label, construído como PWA, para a marca/empresa Evolua Automação (Edmilson Torres) revender/instalar em clientes de varejo, bares e restaurantes.

**Atenção:** este projeto é 100% da Evolua Automação. A Expertize é uma empresa diferente (onde o usuário trabalha atualmente) e não tem nenhuma relação com este sistema — nunca atribuir este projeto a ela.

## Contexto do projeto

- Inspirado no "Link PRO" da Cervantes Tecnologia, mas **sem módulo fiscal** nesta fase (NF-e/NFC-e ficam para depois, via API de terceiros como Focus NFe ou PlugNotas — nunca implementar homologação fiscal própria).
- **White-label**: cada cliente poderá trocar a logo/nome padrão "Evolua Automação" pela própria marca.
- **PWA**, não app nativo: um único código Next.js, instalável via navegador (manifest + service worker), sem build separado para Android/iOS.
- Vai ser usado em divulgação nas redes sociais da Evolua Automação — telas públicas (login, catálogo) devem ficar apresentáveis, mesmo sendo MVP.
- **Multi-loja (multi-tenant) já implementado** (2026-09-18): várias lojas na mesma instalação, cada uma com marca, PIX, taxas, catálogo, usuários e dados isolados. Ver "MULTI-LOJA" no status.

## Escopo dos módulos (MVP)

1. **PDV**: busca de produto, carrinho, pagamento (dinheiro/cartão/PIX), fechamento de venda, recibo interno (não fiscal), histórico de vendas.
2. **Estoque**: cadastro de produtos (nome, SKU, categoria, preço custo/venda, quantidade, unidade), entrada/saída, baixa automática na venda, alerta de estoque baixo.
3. **Catálogo**: listagem por categoria, página pública para visualização (semi-pública, sem carrinho fiscal).
4. **Branding/White-label**: tabela de tenant com logo (upload), nome fantasia, cor primária opcional; logo substitui a marca padrão no header e no manifest do PWA.
5. **PWA**: manifest.json, service worker (via `next-pwa` ou equivalente), ícones, instalação em Android/iOS, cache básico para tolerar internet instável.

## Stack de referência

| Camada | Ferramenta |
|---|---|
| Frontend/App | Next.js (App Router) + React + TypeScript + Tailwind, configurado como PWA |
| Backend | API routes do próprio Next.js |
| Banco de dados | Supabase (Postgres) |
| Deploy | VPS Hostinger (Node.js + Nginx reverse proxy + SSL via Certbot), acesso remoto via VS Code Remote SSH |
| Fiscal (futuro) | API de terceiro homologada (Focus NFe / PlugNotas) — nunca implementar do zero |

## Modelo de dados de referência

```sql
tenants (id, nome_fantasia, logo_url, cor_primaria, ativo)
produtos (id, tenant_id, nome, sku, categoria, preco_custo, preco_venda, quantidade, unidade, ativo)
movimentos_estoque (id, tenant_id, produto_id, tipo [entrada|saida|venda|ajuste], quantidade, criado_em)
vendas (id, tenant_id, total, forma_pagamento, status, criado_em)
itens_venda (id, venda_id, produto_id, quantidade, preco_unitario)
```

Mesmo em single-tenant, incluir `tenant_id` desde já (fixo/único) para facilitar migração futura.
